# 2026年秋版：自律エージェント・推論モデル時代におけるプログラミングスタイル再評価

> [!NOTE]
> 本ドキュメントは、[2026年6月版の総合評価・ランキング](style-ranking.md) に対するアップデート・追記考察です。過去の評価を上書きして消去するのではなく、AI技術の急激な進展（単発コード補完の時代から、長文脈・推論モデル・自律エージェント協調の時代へ）に伴う「パラダイムの変化の歴史」として記録します。

---

## 1. 2026年6月から9月にかけての主なAIパラダイムシフト

わずか数ヶ月の間にも、AIを活用したソフトウェア開発（AI駆動開発）の現場には決定的な変化が生じました。

| 評価軸 | 2026年6月当時（初版評価時） | 2026年9月現在（自律エージェント時代） |
| :--- | :--- | :--- |
| **主要なAIの形態** | コード補完・単一関数の生成ツール（チャットUI） | ツール呼び出し・自己修復・自律駆動エージェント（Agentic AI） |
| **コンテキスト把握力** | 短〜中文脈。複数ファイルにまたがる参照は見失いがち | 100万トークン級の長文脈。プロジェクト全体の依存関係を保持可能 |
| **推論能力 (Reasoning)** | 局所的なパターンマッチングが中心 | 高度な論理推論（思考ステップの明示化、制約充足の解法） |
| **トークン経済性** | 生成トークン数の削減が主眼 | **Prompt Caching（Prefixキャッシュ保護）** による再利用効率が最重要 |
| **エラーへの対処** | 人間がエラーを見て再プロンプトする | テストや型エラーをエージェント自身が観測し**自己修復（Self-Healing）** |

---

## 2. スタイル評価の再逆転・新たな気づき

このパラダイムシフトによって、書籍『プログラミングの文体練習』に登場する各スタイルの評価は大きく再編成されました。

### ① 「小さな局所最適」から「構造的な責務分離」への信頼回復
* **2026年6月当時:**  
  AIのコンテキスト制限から、1つのファイル・関数で完結する `06. Pipeline` や `07. Code Golf` が「AI親和性」で絶賛されていました。
* **2026年9月現在:**  
  長文脈モデルの定着により、`14. Abstract Things`（インターフェース/DI）や `20. Plugins`、`33. Trinity (MVC)` といった**「複数モジュールにまたがる厳格な責務分離」**をAIが一切破綻することなく正確に追従・リファクタできるようになりました。「AIが迷子にならないようにコードを小さくまとめる」時代から、「AIが安全に局所変更できるよう明確なインターフェース境界を敷く」時代へと進化しています。

### ② プロンプトキャッシング（Prompt Caching）が変えた不変性の価値
* **`43. Event Sourcing` / `26. Persistence` / `47. Functional Core, Imperative Shell` の躍進:**  
  現代のLLM APIは、プロンプトの先頭（Prefix）が一致している限り、KVキャッシュが効いてレイテンシとコストが最大9割削減されます。  
  状態を破壊的更新（In-Place Mutation）せず、不変の追記型イベントとして管理するスタイルや、副作用を持たない純粋関数群（Core）は、プロンプトの静的コンテキストとしてキャッシュを極大化させるため、経済的・性能的に圧倒的な優位性を持ちます。

### ③ 自己修復ループ（Self-Healing）を支えるエラー設計
* **`24. Intention-Revealing`（Result型）と `22. Tantrum`（フェイルファスト）の二強体制:**  
  エージェントが自律的にコマンドを実行してエラーを修復する際、暗黙的な例外キャッチ（`23. Passive-Aggressive`）は「何が起きたか分からず修復ループが空回りする最悪のアンチパターン」となりました。  
  型シグネチャで失敗を強制する Result 型（Intention-Revealing）は型チェッカーで即座にAIが自己修復でき、不整合時に詳細なスタックトレースを吐いて即死する Tantrum はエラーログからAIが一発でバグの原因を特定できます。

### ④ エージェント協調（Multi-Agent）と並行・分散スタイルの完全合致
* **`29. Actors` と `16. Bulletin Board`:**  
  複数の専門サブエージェント（Planner、Developer、Reviewerなど）が互いに直接内部状態を覗かず、非同期メッセージパッシング（Pub/SubやMailbox）でやり取りする現代のマルチエージェントシステムの設計思想は、これらのアクター/掲示板スタイルそのものです。

## 3. 2026年秋の追加スタイル（47・48）の意義

このようなパラダイムの変遷を決定づけるものとして、本プロジェクトでは新たに2つのスタイルを追加しました。

### [47. Functional Core, Imperative Shell (FCIS)](style-47-functional-core-imperative-shell.md)
* **位置づけ:** **普遍的・不変の土台アーキテクチャ**
* 副作用ゼロの純粋関数（Core）と外側の薄い命令的シェル（Shell）を分離。
* プロンプトキャッシュの保護、AIによるモック不要の単体テスト自動生成、決定論的な動作保証において、現代のAI駆動開発における最も堅牢な土台スタイルです。

### [48. Agentic Tool Use (ReAct / ツール呼び出し)](style-48-agentic-tool-use.md)
* **位置づけ:** **2026年秋時点の歴史的スナップショット**
* ハードコードされた制御フローを廃止し、各機能を自然言語説明とJSONスキーマを持つ「Tool」として登録。エージェントが ReAct ループ（Thought $\rightarrow$ Action $\rightarrow$ Observation）でゴールを自律的に達成するスタイル。
* 「AIエージェントが普及し始めた2026年当時のプログラミングの姿」を後から振り返るための貴重な指標となります。

## 4. 現代のおすすめスタイル組み合わせパターン (Modern Patterns)

現代のソフトウェア開発において、最も生産性と堅牢性が高まるスタイルの組み合わせです：

```
                    ┌─────────────────────────────────────────┐
                    │  48. Agentic Tool Use                   │
                    │  (自律エージェント・推論ループ)         │
                    └──────────────────┬──────────────────────┘
                                       │ ツール呼び出し
                                       ▼
                    ┌─────────────────────────────────────────┐
                    │  47. Imperative Shell (外側の薄いシェル)│
                    │  ・I/O、コンソール、DBアクセス          │
                    └──────────────────┬──────────────────────┘
                                       │ 純粋引数の受け渡し
                                       ▼
                    ┌─────────────────────────────────────────┐
                    │  47. Functional Core (純粋コア)         │
                    │  ・24. Intention-Revealing (Result型)   │
                    │  ・06. Pipeline (純粋データ変換)        │
                    │  ・不変データ構造 (Prompt Cache 最適)   │
                    └─────────────────────────────────────────┘
```

1. **核 (Core):** `47. FCIS (Core)` ＋ `24. Intention-Revealing` ＋ `06. Pipeline`
   - 副作用ゼロの純粋関数をパイプラインで繋ぎ、失敗はResult型で明示する。キャッシュ効率・テスト性ともに100点。
2. **外殻 (Shell):** `47. FCIS (Shell)` ＋ `14. Abstract Things` (DI)
   - 外部との接点のみを薄いシェルに閉じ込め、インターフェースで疎結合にする。
3. **自律駆動 (Agentic Layer):** `48. Agentic Tool Use`
   - 上記のシェルをToolとしてエージェントに渡し、高レベルなゴールから自律的にシステムを動かす。
